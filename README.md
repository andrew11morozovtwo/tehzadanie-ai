# ТехЗадание AI

Русскоязычный AI-менеджер требований, который помогает заказчику превратить идею цифрового продукта в понятное техническое задание для разработки.

Пользователь отвечает на вопросы в чате, может записать голосовое сообщение или приложить референсы, а затем получает отдельный структурированный документ в форматах **Markdown** и **JSON**. Готовое ТЗ можно проверить в предпросмотре и отправить разработчику по email.

## Зачем нужен проект

На старте продукта важные решения часто остаются в переписке, голосовых сообщениях и разрозненных файлах. «ТехЗадание AI» собирает эту информацию в управляемый процесс:

1. фиксирует идею и контекст проекта;
2. задаёт уточняющие вопросы по пробелам;
3. проверяет, что обязательные темы действительно раскрыты;
4. формирует самостоятельное ТЗ, не копируя в него историю переписки;
5. даёт возможность дополнить проект и собрать новую версию документа.

## Возможности

- регистрация пользователя с выдачей пароля;
- вход, выход и защищённая JWT-сессия в HTTP-only cookie;
- список проектов и сохранение истории диалогов в PostgreSQL;
- AI-интервью на русском языке с контекстом проекта;
- последовательная проверка обязательных тем:
  - цель и проблема;
  - пользователи и роли;
  - главный пользовательский сценарий;
  - функции первой версии;
  - данные;
  - платформа;
  - интеграции;
  - ограничения;
  - критерий успеха;
- не более 10 обычных вопросов интервью;
- команды «Где ТЗ?» и «Собери ТЗ»;
- отображение прогресса и недостающих блоков;
- голосовой ввод с транскрибацией в редактируемый текст;
- загрузка PDF, TXT, JSON, PNG, JPG и WEBP-файлов размером до 10 МБ;
- генерация ТЗ в Markdown и JSON;
- просмотр текущей версии документа;
- возврат из документа в исходный диалог;
- дополнение уже готового проекта с переводом старой версии в черновик;
- отправка готового ТЗ разработчику через Resend;
- фоновый внутренний аудит качества документа;
- техническое логирование ошибок, предупреждений и медленных запросов без текста диалога и персональных данных.

## Как проходит работа пользователя

1. Пользователь регистрируется или входит в аккаунт.
2. Создаёт проект и описывает идею в чате.
3. Отвечает на уточняющие вопросы AI-менеджера.
4. При необходимости добавляет голосовые сообщения и файлы-референсы.
5. Видит прогресс сбора требований и список незаполненных тем.
6. Запускает сборку ТЗ после заполнения обязательных блоков.
7. Проверяет Markdown/JSON-документ в предпросмотре.
8. Отправляет финальную версию разработчику или возвращается к диалогу для дополнений.

## Архитектура

Проект организован как pnpm-монорепозиторий:

```text
artifacts/
├── api-server/             # Express API, авторизация, AI-логика и email-сценарии
├── requirements-manager/   # React/Vite mobile-first интерфейс
└── mockup-sandbox/         # Изолированный сервер предпросмотра компонентов

lib/
├── api-spec/               # OpenAPI-контракт и генерация схем/хуков
├── api-client-react/       # Сгенерированный React API-клиент
├── api-zod/                # Серверные Zod-схемы
└── db/                     # PostgreSQL-схема и Drizzle ORM
```

Основные точки входа:

- `artifacts/requirements-manager/src/` — страницы и компоненты интерфейса;
- `artifacts/api-server/src/routes/requirements.ts` — API проектов, сообщений, файлов и ТЗ;
- `artifacts/api-server/src/lib/requirements-ai.ts` — состояние интервью, команды и генерация документа;
- `artifacts/api-server/src/modules/ai-audit/` — фоновый аудит качества;
- `lib/api-spec/openapi.yaml` — источник API-контракта;
- `lib/db/src/schema/` — таблицы пользователей, проектов, сообщений, файлов и документов.

## AI-провайдер

Все AI-запросы приложения проходят через **ProxyAPI** с OpenAI-совместимым API:

- `gpt-5.6-luna` — интервью и генерация ТЗ;
- `gpt-4o-mini-transcribe` — распознавание голосовых сообщений;
- `gpt-5.6-terra` — внутренний аудит качества.

Стандартный endpoint:

```text
https://api.proxyapi.ru/openai/v1
```

Ключ ProxyAPI используется только на сервере и не попадает в браузер или клиентский код.

## Требования

- Node.js 24;
- pnpm;
- PostgreSQL 16 или совместимый PostgreSQL;
- API-ключ ProxyAPI;
- Resend для отправки готовых документов разработчику.

## Быстрый запуск

### 1. Установить зависимости

```bash
pnpm install
```

### 2. Настроить окружение

Скопируйте пример конфигурации:

```bash
cp .env.example .env
```

Для Replit значения добавляются через Secrets и Environment Variables. Список переменных приведён ниже.

### 3. Подготовить базу данных

Убедитесь, что задан `DATABASE_URL`, затем примените схему в development-окружении:

```bash
pnpm --filter @workspace/db run push
```

### 4. Запустить сервисы

API-сервер:

```bash
pnpm --filter @workspace/api-server run dev
```

Web-интерфейс:

```bash
pnpm --filter @workspace/requirements-manager run dev
```

В Replit оба сервиса запускаются через настроенные workflows.

### 5. Проверить проект

```bash
pnpm run typecheck
pnpm run build
```

## Переменные окружения

### Обязательные

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL |
| `SESSION_SECRET` | Секрет подписи сессий |
| `DEVELOPER_EMAIL` | Получатель готового ТЗ |
| `PROXYAPI_KEY` | Секретный ключ ProxyAPI |

### AI и email

| Переменная | Назначение |
| --- | --- |
| `PROXYAPI_BASE_URL` | OpenAI-совместимый endpoint ProxyAPI; по умолчанию `https://api.proxyapi.ru/openai/v1` |
| `RESEND_API_KEY` | Ключ Resend для отправки писем |
| `RESEND_FROM_EMAIL` | Адрес отправителя, если используется отдельная настройка |

### Внутренний аудит

| Переменная | Назначение |
| --- | --- |
| `AUDIT_ENABLED` | Включить фоновый аудит (`true`/`false`) |
| `AUDIT_DEVELOPER_EMAIL` | Получатель внутреннего отчёта аудита |
| `AUDIT_MODEL` | Модель аудита; по умолчанию `gpt-5.6-terra` |
| `AUDIT_MAX_RETRIES` | Максимальное число повторов аудита |
| `AUDIT_MAX_DIALOG_CHARS` | Лимит текста диалога для аудита |
| `ADMIN_AUDIT_TOKEN` | Токен для административного повтора аудита |

Секреты (`SESSION_SECRET`, `PROXYAPI_KEY`, `RESEND_API_KEY` и `ADMIN_AUDIT_TOKEN`) нельзя коммитить в репозиторий. Для production используйте отдельные значения окружения.

## Основные API-маршруты

Все маршруты приложения доступны с префиксом `/api`:

```text
POST   /api/auth/register
POST   /api/auth/login
POST   /api/auth/logout
GET    /api/auth/me

GET    /api/sessions
POST   /api/sessions
GET    /api/sessions/:id
POST   /api/sessions/:id/message
POST   /api/sessions/:id/finalize

POST   /api/transcribe
GET    /api/sessions/:id/files
POST   /api/sessions/:id/files
DELETE /api/sessions/:id/files/:fileId
GET    /api/sessions/:id/tz
POST   /api/send-tz
```

Полный контракт находится в [`lib/api-spec/openapi.yaml`](lib/api-spec/openapi.yaml).

После изменения OpenAPI-контракта перегенерируйте клиент и схемы:

```bash
pnpm --filter @workspace/api-spec run codegen
```

## Безопасность и данные

- пароль хранится только в виде bcrypt-хеша;
- сессия хранится в HTTP-only cookie;
- AI-ключи доступны только серверу;
- проекты и сообщения изолированы по пользователю;
- логи не должны содержать текст диалога, email и другие персональные данные;
- перед публикацией проверьте production-секреты и не используйте тестовые значения.
