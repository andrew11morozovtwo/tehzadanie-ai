# Авторизация в dev/preview: фактические результаты

> Следующий этап: получатель сохранён владельцем, однократная отправка с `onboarding@resend.dev` подготовлена, но **заблокирована до отдельного согласия**. Актуальные ограничения: [email-auth-preview-mail.md](email-auth-preview-mail.md). Ниже результаты предыдущего этапа с полностью отключённой почтой.

Дата: 2026-11-05. Изменения выполнены по отдельному разрешению пользователя, без публикации, commit/push/merge, настоящих писем, sender/DNS и изменений production.

## База и сохранность

- Реальное подключение preview и managed dev: `heliumdb`. Production read-only: `neondb`. Это разные базы; строки подключения и их значения не выводились и не копировались в TEST_DATABASE_URL.
- Применён `email-auth-schema-review.sql` одной транзакцией: guard dev-имени/роли, lock_timeout 5 секунд, statement_timeout 20 секунд. Добавлены nullable `users.email_verified_at`, nullable `password_hash`, `auth_email_challenges`, `auth_sessions`, пять индексов и ограничения. Очистки, DELETE/TRUNCATE и обновления прежних строк не выполнялись.
- До/после сравнивались количества и агрегатные контрольные суммы **всех прежних строк**, исключая новое nullable-поле. Все шесть прежних таблиц сохранены: users 22, requirement_sessions 35, messages 472, project_documents 30, reference_files 1, audit_reports 21.
- У всех прежних пользователей `email_verified_at IS NULL`; существующие email, хеши, имена, ID, документы, владельцы и содержимое не изменились.
- Тестовые аккаунты используют уникальные синтетические адреса в `example.invalid`. Они и тестовые проекты/документы/файлы оставлены в dev, а не удалены.
- Production-схема и настройки флагов повторно сравнены с началом этапа: без изменений. Production-сессии не отзывались.

## Включение preview

Только development: `EMAIL_AUTH_ENABLED=true`, `VITE_EMAIL_AUTH_ENABLED=true`, `AUTH_PUBLIC_URL` соответствует preview, `AUTH_IP_MAX_PER_HOUR=60`, `AUTH_TRUST_PROXY_HOPS=0`, `EMAIL_AUTH_MAIL_MODE=disabled`.

Preview API/frontend перезапущены; общий `SESSION_SECRET` не менялся. Старый preview-JWT без зарегистрированного sid получает 401. Production-флаги не задавались. Значение trust proxy 0 намеренно не доверяет поддельному X-Forwarded-For; через общий proxy пользователи могут разделять IP-лимит. Это не проверенная production-настройка.

Dev-only отключение почты:
- запрос реального письма возвращает явный 503 **до создания challenge**;
- сервис доставки не может вызвать Resend, уведомление о новой подтверждённой регистрации подавлено;
- восстановление старых аудитов при старте dev пропущено, чтобы не менять существующие записи и не возобновить отправки;
- вне NODE_ENV=development такой mail mode не запускается;
- обычные функции отправки ТЗ не заменены тестовым почтовым ящиком; тесты их не вызывают.

## Выполненные проверки

- TypeScript: общие библиотеки, API, frontend и новый PostgreSQL-тест.
- 98 автоматических offline/HTTP/JWT/клиентских проверок, включая четыре сочетания флага и базового пути.
- 7 отдельных проверок с настоящим PostgreSQL / работающим preview API:
  1. Запрос и inspect не создают аккаунт; явное подтверждение создаёт одного подтверждённого пользователя; повторное погашение отклоняется.
  2. Восемь конкурентных подтверждений одного токена: ровно один успех, семь отказов used, одна серверная сессия.
  3. Искусственная ошибка **после INSERT сессии**: ROLLBACK аккаунта, подтверждения, погашения и сессии; тот же токен затем работает.
  4. Специально созданный «старый» тестовый аккаунт требует ссылку и правильный пароль; неверный/отсутствующий пароль не подтверждает; ID и хеш сохраняются.
  5. Шесть параллельных запросов ссылки на один тестовый адрес: один accepted, пять limited.
  6. Live API: создание тестового проекта, доступ владельца и 404 другому тестовому пользователю для проекта/сообщений, ТЗ и файлов. Legacy-JWT без sid — 401; после logout скопированная cookie — 401.
  7. Одно подменённое письмо для свежего синтетического аккаунта, приватная временная ссылка для браузерной проверки без вывода токена.
- Один настоящий браузерный прогон этой синтетической ссылки: GET показывает имя и явную кнопку «Войти», сам не авторизует; подтверждение открывает новый аккаунт, reload сохраняет вход, выход возвращает форму email, повторная ссылка показывает «Эта ссылка уже использована». Фрагмент убран из наблюдаемых URL. Писем не запрашивал, прежние аккаунты не открывал.
